Веб-приложение на чистых сервлетах и JSP по шаблону MVC.  
Пользователь вводит/выбирает координаты точки (**x**, **y**) и радиус **R**,  
а сервер проверяет, попадает ли эта точка в заданную составную область на координатной плоскости.

🖱 Поддерживается клик по области на графике — координаты X/Y вычисляются на клиенте и автоматически отправляются.  
📜 История всех проверок хранится в сессии и отображается в таблице.  
🗑 Историю можно очистить кнопкой.

---

## 🧠 Задача

1. Форма на странице (`index.jsp`) собирает:
   - `x`: дискретно (кнопки от −5 до 3),
   - `y`: ввод текстом, число от −5 до 5,
   - `r`: выбором из {1,2,3,4,5}.
2. Можно кликнуть по изображению области.  
   JS пересчитает пиксель в координаты (x,y) с учётом выбранного R → отправит форму.
3. Сервер:
   - валидирует параметры,
   - проверяет попадание точки в составную фигуру,
   - добавляет результат в историю.
4. История отображается прямо на главной странице: дата, время, x, y, r и «попадание / мимо».
5. Есть отдельная кнопка «Очистить историю», которая сбрасывает сессионный список.

## 🏗 Архитектура (MVC)

### Model (`src/main/java/com/K1ll4a/model`)
- `Point` — данные о точке (x, y, r).
- `HitResult` — одна проверка (точка, флаг попадания, метка времени).  
  Даёт уже готовые строки `getDateStr()` и `getTimeStr()` для таблички.
- `HitListBean` — список всех `HitResult`, хранящийся в HTTP session.

### Controller (`src/main/java/com/K1ll4a/controller`)
- `ContollerServlet`  
  - принимает POST из формы `/controller`,  
  - валидирует входные параметры,  
  - при успехе форвардит на `/area-check`.
- `AreaCheck`  
  - вычисляет факт попадания точки в область,
  - добавляет запись в `HitListBean` (история в сессии),
  - отдаёт `result.jsp`.
- `ClearHistory`  
  - обнуляет историю в сессии по `POST /history/clear`,
  - редиректит обратно на главную.

### Service (`src/main/java/com/K1ll4a/sevice`)
- `ValidationService`  
  - парсит x / y / r из запроса,
  - проверяет диапазоны,
  - формирует структуру `Parsed`.
- `AreaCheckService`  
  - знает геометрию области (объединение трёх фигур: прямоугольник, треугольник, сектор четверти круга),
  - решает «попадание» или «мимо».

> Контроллеры не делают математику сами и не работают с JSP напрямую — они делегируют в сервисы и кладут данные в `request`/`session`.

## 🎨 View (`src/main/webapp`)

### `index.jsp`
- ФИО / группа / номер варианта (можно подставить свои данные).
- Выбор `x` кнопками `-5 .. 3`.
- Поле `y` (строковый ввод).
- Выпадающий `r`.
- Блок «График области»:
  - статика `graph.png`,
  - прозрачный `<canvas>` поверх,
  - JS слушает клик, вычисляет (x,y), отправляет форму.
- Таблица «История проверок» (JSTL `<c:forEach>`):
  - колонки: Дата, Время (без миллисекунд), X, Y, R, Результат (`попадание` / `мимо`).
- Кнопка «Очистить историю» → POST `/history/clear`.

### `result.jsp`
- Краткий вывод последнего результата проверки.
- Ссылка «Назад», чтобы вернуться к форме.

### `static/`
- `static/images/graph.png` — картинка области, по которой кликает пользователь.
- `static/js/app.js` — фронтовая логика:
  - выбор X по клику на кнопку,
  - client-side валидация полей,
  - пересчёт клика на графике в координаты,
  - автосабмит формы.

## 🐳 Запуск в Docker с WildFly

Чтобы приложение крутилось в контейнере и преподавателю было удобно проверять,  
используется кастомный Dockerfile, который:

1. Собирает `.war` через Maven (Java 17).
2. Кладёт `.war` в WildFly 26.1.3.Final (версия до миграции на `jakarta.*`, то есть с `javax.servlet.*`).
3. Запускает WildFly c биндингом `0.0.0.0`, чтобы можно было пробросить порт наружу.

Почему так сложно?
- Новые WildFly (38+) уже на `jakarta.servlet.*` и не поднимут старые сервлеты/JSP без миграции.
- Мы разворачиваем именно WildFly 26.x, который полностью совместим с `javax.servlet` и JSTL.
